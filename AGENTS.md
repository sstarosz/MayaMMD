# AGENTS.md

Instructions for any AI agent working in this repository.

MayaMMD is an Autodesk Maya plugin (C++ native module + Python package) that imports MMD models,
motions and poses. Supports Maya 2024–2027 on Windows, Linux and macOS.

## Read before you change

1. `docs/CPPDevelopment.md` — build, tests, and the rigid-body performance invariants.
2. `.agents/skills/` — six skills with the rules that decide whether a change is acceptable:
   `mayammd-architecture`, `mayammd-physics-invariants`, `mayammd-maya-matrix`,
   `mayammd-conventions`, `mayammd-testing`, `mayammd-changelog-release`. Load the ones that
   match the area you touch; a plan that ignores `mayammd-physics-invariants` while editing
   `rigid_body_*` is wrong even if it compiles.
3. `docs/CustomAttributes.md`, `docs/JointVisualization.md`, `docs/MorphImplementation.md`,
   `docs/NamingConventions.md` for the area you touch.

## The non-negotiables

1. `mmd/core` stays Maya-free and Bullet-free; Bullet types only inside `bullet_bridge`.
2. Python and C++ talk only through Maya attributes and plugs. No ctypes, no shared structs.
3. Do not add cross-node `MPlug` reads inside per-frame `compute()` or display paths. Per-frame
   data the solver needs is a real input read through its own `MDataBlock` (like
   `bodyAnchors[i]`); configuration is cached and invalidated by dirt on the owning node's own
   inputs, reported from both `setDependentsDirty` and `preEvaluation`. No scene-wide serials.
4. Do not re-enable VP2 `requiresGeometryUpdate()` / `requiresUpdateRenderItems()`, and do not
   switch to `MRenderItem::setMatrix()`.
5. Names, attribute long names, enum values, type ids and classifications are persisted in saved
   scenes. Renaming any of them is breaking: document the re-import.
6. Bodies and joints keep **PMX order**; a dropped body shifts every later constraint index.
7. Keep the rest-pose vs current-pose split and the `K = jointRestWorld × bodyRestWorld⁻¹` offset.
8. Maya APIs newer than 2024 go behind `MAYA_API_VERSION` guards with a working fallback.
9. New C++ files must be added to the `MayaMMD` target in `CMakeLists.txt` and registered in
   `MayaMMD.cpp`; a file that is not listed is silently not built.
10. Never commit binary assets (`.pmx`, `.vmd`, `.vpd`) or generated file lists; they are gitignored.

## Before you call a change done

```bash
ruff format --check mmd tests
ruff check mmd tests
mypy mmd tests
pytest tests/unit_tests tests/integration/core/ --ignore=scripts --ignore=tests/integration/maya
```

If you touched C++, also configure a **Ninja** build and run clang-format/clang-tidy there —
`out/build/maya2026-release` is a Visual Studio build with no `compile_commands.json`. Configure with
`-DBUILD_DEV_INSTALL=OFF` unless you mean to install into Maya.

Add a `CHANGELOG.md` bullet under `## [Unreleased]` for any user-visible change, in the style of the
existing entries. Use the PR body sections `## Summary` / `## Changes` / `## Validation`, where
Validation lists commands actually run and their results.

A suite that was skipped is not a pass. Say which gate did not run.

## Do not

- Edit `mmd/_version.py` (generated by CMake), `assets/*_database/`, or the generated `*_files.py`.
- Build into the user's Maya install by accident: `-DBUILD_DEV_INSTALL=OFF`.
- Report "2024–2027 supported" as tested when only 2026 was built.
- Trust `docs/PhysicsPanelFollowUpTasks.md` as a description of current behaviour; it is a plan.
